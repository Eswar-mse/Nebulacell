<h3>WHAT IS NEBULACELL</h3>
</div>

**NebulaCell** is an interactive, GPU-accelerated dashboard for exploring spatial single-cell and spot data. Load a real `.h5ad` file, look at it in your browser, recolour it by any gene, find tissue domains by density, and ask questions in plain language, all in one tab and without a notebook.

Spatial transcriptomics couples gene expression with physical tissue coordinates, but most exploratory tooling either stops scaling past a few thousand points or needs notebook-driven analysis for every question. NebulaCell aims for an interactive middle ground. It has been stress-tested on real public datasets from **2,800 to 827,000+ cells** across **Visium**, **MERFISH** and **Xenium** assay types.

> [!NOTE]
> **In plain terms.** A normal single-cell experiment tells you *what* each cell expresses. A spatial one also tells you *where* the cell sits in the tissue. NebulaCell draws every cell at its x/y position, so you can see tissue structure and its gene activity together.

<h3>HOW IT WORKS</h3>
</div>

```mermaid
flowchart LR
    F[("spatial .h5ad")] --> L["loader.py<br/>in-memory or backed"]
    L --> IMG["image_overlay.py<br/>Visium histology"]
    L --> H["hdbscan_runner.py<br/>adaptive spatial domains"]
    L --> Q["parser.py<br/>NL query to filter"]
    IMG --> APP
    H --> APP
    Q --> APP
    APP["Dash app<br/>main.py"] --> GL[/"Plotly Scattergl<br/>WebGL in your browser"/]
    classDef box fill:#0A1224,stroke:#2563EB,color:#93C5FD
    class F,L,IMG,H,Q,APP,GL box
```

**Under the hood.** Four ideas make it work:

1. **WebGL, not SVG.** Points are drawn with Plotly's `Scattergl`, so the GPU does the work. Plain SVG scatter plots start to struggle past roughly 10 to 20 thousand points, while NebulaCell has been tested at 827,000 cells without the browser choking.
2. **Two ways to cluster.** *Leiden clusters* group cells by how similar their **expression** is. *HDBSCAN domains* group cells by how densely packed they are in **space**. Switch between the two views to compare "what cells are" with "where they sit".
3. **Adaptive tuning.** HDBSCAN's `min_cluster_size` and `min_samples` default to values scaled to the dataset size. The **Recluster** control lets you change them and re-run instantly, without reloading the data.
4. **Smart loading.** NebulaCell picks in-memory or backed-mode loading from the real matrix size (cells × genes), not from the cell count alone.

<details>
<summary><b>What is HDBSCAN, in one minute?</b></summary>

<br/>

HDBSCAN is a density-based clustering method. Instead of asking you for the number of clusters up front, it looks for regions where points are packed closely together and treats sparse points as noise. `min_cluster_size` sets the smallest group worth calling a domain, and `min_samples` controls how conservative the density estimate is: higher values mark more points as noise. That is why it suits tissue, where regions have irregular shapes and no fixed count.

</details>

<h3>FEATURES</h3>
</div>

| | Feature | What you get |
| :---: | :--- | :--- |
| ⚡ | **GPU-accelerated rendering** | WebGL via Plotly `Scattergl`, tested up to 827,000 cells |
| 🔬 | **Histology overlay** | Tissue image extracted from Visium-style `.h5ad` files (`adata.uns['spatial']`) and scaled to match spot coordinates. Degrades gracefully for MERFISH and Xenium, which have no histology image |
| 🧭 | **Dual clustering views** | Expression-based Leiden clusters (if present in the file) next to independently computed HDBSCAN spatial domains |
| 🎛️ | **Adaptive HDBSCAN** | Defaults scale with dataset size, plus a live **Recluster** control |
| 🧬 | **Live gene exploration** | Searchable gene dropdown recolours the whole dataset. Hover tooltips show each cell's top-expressed genes and the selected gene's value |
| 💬 | **Natural-language filtering** | Type `show cells with high Xkr4` or `show cluster 3`. A rule-based parser, with no LLM API cost, validates against the dataset before filtering |
| 📂 | **Real `.h5ad` loading** | Point it at any spatial `.h5ad` file through a path input |

<h3>QUICK START</h3>
</div>

```bash
git clone https://github.com/Eswar-mse/Nebulacell.git
cd Nebulacell/nebulacell

python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate

pip install -r ../requirements.txt

python -m app.main
```

Open **http://127.0.0.1:8050** in your browser. NebulaCell starts with a small built-in demo dataset (Visium mouse brain, 2,800 cells), so you can try it with no download or setup.

> [!TIP]
> To load your own data, paste the path to any spatial `.h5ad` file into the path input. Full instructions are in [USAGE.md](USAGE.md).

<h3>NATURAL-LANGUAGE QUERIES</h3>
</div>
<a id="natural-language-queries"></a>

**In plain terms.** Type a sentence into the query box and the matching cells light up.

| You type | NebulaCell does |
| :--- | :--- |
| `show cells with high Xkr4` | Highlights cells with high expression of the gene `Xkr4` |
| `show cluster 3` | Highlights the cells that belong to cluster 3 |

**Under the hood.** A rule-based regex parser turns your sentence into a structured filter and **checks it against the loaded dataset** (does that gene exist? does that cluster exist?) before anything is applied. There is no model call, so it costs nothing, behaves the same every time, and cannot hallucinate.

> [!IMPORTANT]
> The grammar is deliberately narrow. It covers gene-expression-level and cluster-membership queries, and it is not a general-purpose language interface.

<h3>LIMITATIONS AND ROADMAP</h3>
</div>
<a id="limitations-and-roadmap"></a>

Being upfront about what v1 does not do yet:

> [!CAUTION]
> **No true out-of-core computation.** Backed-mode loading currently speeds up only the initial read of very large files. Clustering and gene lookups still bring the full matrix into memory.

- **Gene symbols.** There is no symbol-mapping layer yet, so Ensembl-ID datasets show IDs.
- **Narrow query grammar.** This is a deliberate choice: zero API cost, fully predictable, no hallucination risk.
- **Local-first, single user.** No authentication, multi-user sessions or cloud deployment. It is a research tool for one person's machine.

**Planned for v2:** real streaming / chunked computation for out-of-core data.
